# 课程知识星图使用说明

## 现在的流程

登录进入学习空间 → 我的课程 → 创建课程或打开已有课程 → 导入资料（可选）→ 配置知识星图 → 手动添加知识点、说明、先后关系 → 可选关联本人复习任务 → 保存并查看。

也可以新建课程后直接配置，再逐步补充资料。没有星图不会阻止登录、浏览课程或上传资料。星图不会自动创建课程，也不限定课程学科。

## 页面操作

1. 在“我的课程”新建任意名称的课程；真实账号会保存到后端。
2. 打开课程详情，可导入 TXT / Markdown / PDF，或点击“配置知识星图”。
3. 添加知识点，自行填写名称和说明。可以不关联任务，也可以选择已保存到账号的复习任务。
4. 选择“连线起点”和“连线终点”，点击“添加连接”；可以构造分支，不能形成先后循环。SVG 箭头表示方向。
5. 使用“自动排布节点”，或在每个知识点的“调整节点位置”中手动设置位置。
6. 保存后进入本课程的知识路线。总览和知识路线均可切换课程，各门课程分别保存。
7. 任务完成或删除后，再进入知识路线可看到最新状态；任务删除只解除关联，不删除知识点。任务完成不等于知识能力评分。

上限为每门课程 50 个知识点、150 条连接。标题最多 80 字，目标 180 字，知识点名称 80 字，说明 5000 字。保存整个星图是一次事务，不会只保存一半。

## 旧本机数据

以前只保存在浏览器的课程、资料和任务不会被接口返回值静默覆盖。

- 本机课程标明“尚未同步”。在课程详情点击“同步课程并配置星图”，将课程信息保存到账号，并把旧本机资料指向新的课程 ID。
- 旧本机资料仍在本机，不会假称已经上传；需要跨设备使用时，在同步后的课程中重新导入。
- 本机任务可以在“复习计划”中编辑保存到账号，再回到编辑器刷新任务列表进行关联。
- 体验模式保持本机数据模式；保存课程星图需要登录真实账号。

上一版生成的学科课程和节点保留在原来的课程下，可选择该课程继续编辑；旧 `/setup-knowledge` 链接现在跳转“我的课程”。旧的账号模板创建接口已停用。

## 前后端数据流

```text
创建课程：Courses → services/courses.createCourse → POST /courses → MySQL courses
导入资料：CourseDetail → uploadMaterial → multipart POST /courses/{id}/materials
读取星图：总览/知识路线/编辑器 → loadCourseGraph(courseId) → GET /courses/{id}/knowledge
保存星图：CourseKnowledgeEditor → saveCourseGraph → PUT /courses/{id}/knowledge
任务：Plan → tasks API → MySQL tasks → 节点可选关联 taskId
```

星图以 `(登录用户, courseId)` 隔离。前端按课程缓存，切换账号时清空；请求完成前账号变化时丢弃旧响应。节点连接使用稳定节点 ID，接口另返回与当前节点数组配套的 `edges`，用于现有 SVG 组件。

账号课程、导入资料、手动星图和复习任务已接入接口。研习室问答、练习、错题、报告等仍沿用项目原有逻辑，本次没有宣称它们已经完成全部联调。

## 接口与参数

调试入口：`http://127.0.0.1:8000/docs`，分类“课程知识星图”。所有字段都有 description。请求需要 `Authorization: Bearer <accessToken>`。

- `GET /api/v1/courses/{course_id}/knowledge`：读取本人已经存在的课程；未配置时返回空节点、`configured=false`，不是错误。
- `PUT /api/v1/courses/{course_id}/knowledge`：整图保存。路径 ID 来自课程列表/创建接口，不是课程名称。

```json
{
  "title": "网络实验任务星图",
  "goal": "完成协议实验和实验报告",
  "revision": 0,
  "nodes": [
    {"id": "network-layer", "label": "网络分层", "description": "整理各层功能", "x": 120, "y": 150, "taskId": null},
    {"id": "tcp", "label": "可靠传输", "description": "完成抓包实验", "x": 620, "y": 90, "taskId": null}
  ],
  "links": [{"source": "network-layer", "target": "tcp"}]
}
```

- `revision` 从读取响应中取得；新图为 0，保存后递增。旧版本提交返回 409，编辑内容保留，可明确点击“重新加载最新星图”放弃未保存内容后重新编辑。
- `taskId` 可为 null；关联时必须是本人任务 ID，不可使用示例 ID 或别人的任务。
- `nodes=[]`、`links=[]` 可以清空当前课程的图，不删除课程和资料。
- `links` 不允许自连、重复、引用不存在节点或形成有向循环；参数不合法返回 422。
- 不存在或无权访问的课程/任务返回 404；服务故障会显示错误，不能回退到示例图。
- 前端 Axios 封装已返回响应体，不再取 `.data`。上传使用 FormData，由浏览器生成 boundary；PDF 预览使用带鉴权的 Blob 请求。

## 文件位置

前端 `D:/zhiqu-app`：

- `src/views/CourseKnowledgeEditor.vue`：课程手动编辑和预览，Less 写在本组件。
- `src/services/course-knowledge.js`：按课程读取、缓存和整图保存。
- `src/services/courses.js`：课程、资料与任务接口，以及旧本机课程同步。
- `src/mixins/courseGraph.js`：总览与知识路线共用的课程选择和读取逻辑。
- `src/views/Courses.vue / CourseDetail.vue / Plan.vue`：课程、导入与复习任务操作。
- `src/router/index.js`：只检查登录；编辑地址 `/app/courses/:id/knowledge/edit`。

后端 `D:/zhiqu-backend/backend`：

- `app/course_knowledge.py`：请求/响应模型、关系校验、读取与事务保存函数。
- `app/models.py`：`CourseKnowledgeConfig`、`KnowledgeTaskLink`。
- `migrations/versions/0004_course_knowledge.py`：增量新增两张表。
- `docs/接口参考.md / 函数参考.md / 数据库表结构.md`：自动生成的接口、函数和表结构说明。

## MySQL 8.0 与启动

沿用已有 `.env`，数据库连接参数和 SMTP 配置不用更改。0004 只新增 `course_knowledge_configs`、`knowledge_task_links`，保留 0003 历史表与原课程资料。新服务要求迁移到 0004。

```powershell
cd D:\zhiqu-backend\backend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

已有数据库不要重新执行初始化 SQL，不要删除库。若后端已启动，仅在必要时重启原进程。前端按原方式运行 `npm run dev`；使用 preview 时先 `npm run build` 再刷新。

## 验证

- 前端：`npm run build`、`npm run test:knowledge`。回归临时使用 5190 端口，API 是测试夹具，不会写用户库。截图在 `test-results/course-knowledge`。
- 后端：`python -m pytest -q`。默认测试引擎为显式注入的隔离 SQLite；未启用的 MySQL 并发用例会跳过。
- 本次另用独立 FastAPI 服务与隔离数据库，完成了无 API 模拟的真实界面联调（创建课程、导入、任务、手动星图、刷新）。用户 MySQL 只应用新增结构，不写测试账号或测试学习记录。
