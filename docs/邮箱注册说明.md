# QQ 邮箱验证码注册：配置与使用

本版已加入完整注册页面 `#/register`，并将邮箱注册、真实账号登录、刷新验证和退出串通。本地体验入口仍可用；真实账号的本机课程/练习缓存按用户 ID 隔离。

## 1. 获取 QQ 邮箱 SMTP 授权码

登录 QQ 邮箱网页版，点击右上角头像，进入 **设置 → 账号与安全 → 安全设置**，开启 POP3/IMAP/SMTP 服务，再点击 **生成授权码**，按网页指引完成身份验证。授权码用于第三方程序登录，不是 QQ 密码。

QQ 官方当前操作说明：[如何生成授权码](https://help.mail.qq.com/detail/106/985)。发件配置采用 `smtp.qq.com`、SSL 465，参见[腾讯云邮箱 SMTP 配置](https://intl.cloud.tencent.com/zh/document/product/1266/71700)。

不要把授权码发到聊天或写进 Vue；在下面的后端 .env 中填写即可。更改 QQ 密码或主动失效授权码后，需要重新配置。

## 2. 填写 backend/.env

保留已有 MySQL 配置，在 `.env` 添加：

```dotenv
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURITY=ssl
SMTP_USERNAME=你的完整QQ邮箱@qq.com
SMTP_PASSWORD=QQ邮箱生成的SMTP授权码
SMTP_FROM=你的完整QQ邮箱@qq.com
SMTP_TIMEOUT=10
EMAIL_CODE_SECRET=独立生成的随机密钥
```

SMTP_USERNAME 与 SMTP_FROM 通常填同一个 QQ 邮箱。这个邮箱是网站的发件人，注册用户可以使用其他支持正常收信的邮箱，并不限于 QQ。

在自己的终端生成一次独立随机密钥，复制到 EMAIL_CODE_SECRET，长期保存：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

密钥至少 32 字符，不要照抄示例文字，不要每次启动重新生成；更换它会使尚未使用的验证码失效。SMTP 授权码和此密钥只保存在后端 `.env`，不进入接口响应或日志。

发信使用验证服务器证书的 TLS。默认 SSL，也支持 `SMTP_SECURITY=starttls` 配合供应商对应端口，不提供明文 SMTP。

## 3. 升级 MySQL 表结构

在 backend 目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\check_database.py
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

新增迁移 **0002**：

- 新增 email_verifications，持久保存验证码摘要、到期时间、尝试次数与发送额度。
- users 增加 email_verified。旧账号不会被伪标为已验证，仍可按原密码登录；新注册必须验证码通过。
- 保留已有课程、资料、题目和成绩；不要删除数据库重新初始化，也不要修改旧的 0001。

全新数据库会依次执行 0001、0002；已有 0001 的数据库只执行新增部分。正常版本检查应显示 0002，共 11 张业务表及 alembic_version。

## 4. 在浏览器使用

启动 Vue 前端后打开 `#/login`，点击“使用邮箱注册”，或直接进入 `#/register`：

1. 填写昵称和收件邮箱，点击“获取验证码”。
2. 后端通过 QQ SMTP 发信；界面显示 60 秒重发倒计时。
3. 收到邮件后输入 6 位验证码，设置 8～128 位密码并确认。
4. 点击“验证邮箱并注册”；成功后显示验证完成，账号已登录。
5. 点击“进入学习空间”；刷新时通过 /auth/me 恢复会话。

邮箱变化会清空原验证码，各邮箱的冷却时间分别保留在当前表单中。密码保留原始空格，不保存到浏览器。确认密码只用于前端校验，不发送后端。

账号和个人资料已接后端；课程、资料阅读、练习等业务仍按当前页面本机逻辑运行，界面有提示，真实账号首次为空。本地体验继续使用原样例空间。登录/退出时清理旧练习草稿和临时 PDF URL，避免切换账号后显示旧内容。

## 5. 接口调用

### 发送验证码

`POST /api/v1/auth/email-code`，无需登录：

```json
{"email":"student@example.com"}
```

成功返回：

```json
{
  "message":"验证码邮件已发送，请检查收件箱或垃圾邮件",
  "expiresIn":300,
  "resendAfter":60
}
```

响应永远不返回验证码。成功表示 SMTP 接受了邮件，不代表收件箱已即时投递；请检查垃圾邮件或稍后刷新。

### 验证后注册

`POST /api/v1/auth/register`：

```json
{
  "name":"小林",
  "email":"student@example.com",
  "password":"StudyDemo123!",
  "verificationCode":"邮件中的6位数字"
}
```

用真实数字替换上面的说明文字，保留开头的 0。成功返回 accessToken/user，其中 user.emailVerified=true，正式账号默认不创建样例成绩。

| 状态 | 含义 |
| --- | --- |
| 400 | 验证码错误、过期、已使用或错误次数用尽 |
| 409 | 邮箱已注册或发送请求冲突 |
| 422 | 邮箱/密码/验证码字段格式错误 |
| 429 | 正在冷却或配额用尽，读取 Retry-After 秒数 |
| 503 | SMTP 尚未配置、发送失败或数据库不可用 |

## 6. 验证规则与失败处理

- 6 位安全随机数字，5 分钟有效，成功后只消费一次。
- 重发间隔 60 秒；同一邮箱每小时最多 5 次发送尝试。即使 SMTP 失败也计入额度，防止反复触发外部连接。
- 每个验证码最多输错 5 次；次数存数据库，HTTP 错误回滚不会把失败计数撤掉。
- 数据库只保存邮箱/发送批次绑定的 HMAC，不保存明文验证码。SMTP 成功后才激活对应批次。
- 发送时先提交冷却和额度，释放数据库事务后才等待 SMTP；并发发送通过行锁与主键防重。
- IP 每小时最多请求 30 次；当前 IP 限制为单进程，默认单 worker 运行。邮箱冷却和配额保存在数据库。
- 未配置邮件服务时返回明确错误，不打印验证码冒充发送成功，不提供关闭注册验证的运行开关。

QQ SMTP 可能因授权码、服务开关、网络出站限制或供应商发送限制失败。检查后端配置、垃圾邮件和 QQ 邮箱发送记录；不要把原始授权码/验证码贴进错误反馈。

## 7. 验证边界

本轮自动检查使用捕获邮件与模拟 SMTP，没有向真实收件人发邮件，也未读取你的授权码。真实 QQ 投递需要你按上述步骤配置后在注册页测试；MySQL 真实连接仍需填写自己的数据库密码并执行迁移。
