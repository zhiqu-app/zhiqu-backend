# MySQL 8.0：配置、初始化和启动

本项目使用 SQLAlchemy 2 ORM + PyMySQL 连接你已安装的 MySQL 8.0。无需为正式运行再安装 SQLite，也不需要另装 Docker。

## 1. 准备 Python

使用 Python 3.11 或更新的兼容版本。打开 PowerShell：

```powershell
cd D:\zhiqu-app\backend
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

如果 python 命令不可用，可以用已安装的 Python Launcher：`py -3.12 -m venv .venv`。以下命令直接调用虚拟环境，不需要先激活它。

## 2. 在 MySQL 创建专用数据库与用户


在 MySQL Workbench 使用你安装数据库时设置的管理员账号连接本机服务，默认地址 127.0.0.1、端口 3306。执行前先查看 `sql/00_create_database.sql`，将两个密码占位符换成自己设置的应用密码；也可以在查询窗口执行：

```sql
CREATE DATABASE IF NOT EXISTS zhiqu_team
  CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;

CREATE USER IF NOT EXISTS 'root'@'localhost'
  IDENTIFIED BY '替换成你自己的应用密码';

CREATE USER IF NOT EXISTS 'root'@'127.0.0.1'
  IDENTIFIED BY '替换成你自己的应用密码';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
  ON zhiqu_team.* TO 'root'@'localhost';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
  ON zhiqu_team.* TO 'root'@'127.0.0.1';
```

如果代码不可用说明你的名字或者mysql启动有错误，也可以自己进行手动创建数据库名为zhiqu_team。

这两个账号条目只允许本机连接，适配 localhost / 127.0.0.1 的来源匹配；密码请设置一致。`IF NOT EXISTS` 不会替已有账号改密码。如果以前已经创建了同名账号，填写它现有的密码，或由数据库管理员按团队约定调整。

上述 DDL 权限供开发时执行迁移。生产部署应另设迁移账号，运行账号只保留 SELECT/INSERT/UPDATE/DELETE。不要把业务服务配置为数据库 root。

## 3. 配置文件上传所需数据包大小

支持 20 MB PDF 时，MySQL 的 `max_allowed_packet` 至少需要 64 MB。管理员先查询：

```sql
SELECT @@max_allowed_packet;
```

不足 67108864 时，再执行：

```sql
SET PERSIST max_allowed_packet = 67108864;
```

执行后重新建立应用连接。也可以在 MySQL 的 my.ini 的 `[mysqld]` 下配置 `max_allowed_packet=64M`，然后按你的安装方式重启数据库服务。应用账号不需要系统变量管理权限。

## 4. 填写 backend/.env

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

用编辑器打开 `.env`：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=zhiqu_team
MYSQL_USER=zhiqu_team_app
MYSQL_PASSWORD="刚才为应用用户设置的密码"

CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:4173,http://localhost:4173
SESSION_HOURS=168
DEMO_ENABLED=true
```

| 配置 | 作用 |
| --- | --- |
| MYSQL_HOST | 数据库服务地址；当前前后端都在本机时填 127.0.0.1 |
| MYSQL_PORT | MySQL 端口，默认 3306；不是 FastAPI 的 8000 |
| MYSQL_DATABASE | 第 2 步创建的数据库名 |
| MYSQL_USER / MYSQL_PASSWORD | 应用数据库账号与密码，不是网页登录账号 |
| CORS_ORIGINS | 允许调用 API 的前端来源，逗号分隔；协议、主机和端口都要匹配 |
| SESSION_HOURS | 真实账号会话有效小时数，默认 168；体验会话固定 24 小时 |
| DEMO_ENABLED | 是否允许 `/auth/demo` 创建独立体验账号 |

密码包含 # 或空格时请加引号。程序使用 URL.create 构建连接串，不需要手动对 @、#、冒号做 URL 编码。`.env` 已在忽略规则中，不要提交或放到前端。

## 5. 检查连接并初始化表

```powershell
.\.venv\Scripts\python.exe scripts\check_database.py
```

该脚本只读检查数据库版本、数据包大小和迁移版本，不建表、不清库、不打印密码。首次提示“未初始化”后运行：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

会创建 14 张业务表与 alembic_version。随后可在 Workbench 验证：

```sql
USE zhiqu_team;
SHOW TABLES;
SELECT version_num FROM alembic_version;
```

迁移版本应为 0004。项目附带的 schema-review.sql 供审查，正常建表使用 Alembic，不要把两种建表方式重复执行。修改 ORM 结构后应生成和审阅新的迁移，不要改掉已执行的 0001/0002。

如果此前已经安装过相同 ORM 版本，可以连接原来的专用库并检查版本；不要删除已有表来重装。其他旧版演示库的表结构不同，请使用单独数据库。

## 6. 启动接口服务

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- 调试接口：http://127.0.0.1:8000/docs
- 阅读文档：http://127.0.0.1:8000/redoc
- 服务入口：http://127.0.0.1:8000/api/v1
- 健康检查：http://127.0.0.1:8000/api/v1/health

只有数据库连接、迁移版本、数据包大小符合要求时服务才会启动。修改 `.env` 后重启后端；`--reload` 主要监测代码，不应依赖它自动读取环境配置。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 2003 / Connection refused | MySQL 未启动，或地址/端口不正确 |
| 1045 / Access denied | 应用密码、账号来源或授权不匹配；检查错误里的 user@host |
| 1049 / Unknown database | 尚未建库，或 MYSQL_DATABASE 填错 |
| 提示先运行 Alembic | 连接到了未迁移或其他版本的库，先核对库名再迁移 |
| max_allowed_packet 错误 | 管理员配置至至少 64 MB，重建应用连接 |
| 前端 CORS 错误 | 核对浏览器实际来源，包括 Vite 自动换用的端口 |
| 8000 被占用 | 关闭不需要的旧服务，或更换后端端口并同步前端 BASE 地址 |

本次没有读取你的 MySQL 密码，也没有自动创建或修改本机数据库。按本文配置后再做真实连接检查。
