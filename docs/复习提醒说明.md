# 复习计划与实时学习提醒

本版本在原任务和判题接口上增加两类计划、按计划独立保存的习题进度，以及可重新读取的到期/完成通知。

## 部署与迁移

1. 停止旧服务并备份数据库，再执行 `python -m pip install -r requirements.lock.txt`。WebSocket 运行时显式依赖 `websockets==15.0.1`，仅安装 bare `uvicorn` 不足以保证真实握手。
2. 在后端目录运行 `python -m alembic upgrade head`，目标版本为 **0006**。应用启动会检查该版本；请先升级再启动。
3. 启动单 worker：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --ws websockets --ws-max-size 4096`。
4. `CORS_ORIGINS` 必须包含浏览器实际访问的前端 origin（协议、域名、端口完全匹配）。HTTPS 页面须通过 WSS 访问反向代理；代理需要转发 Upgrade/Connection，并允许客户端每 25 秒左右 ping。

0005 为 MySQL 8.0 添加任务字段、`task_questions`、`task_attempts`、`notifications` 与所有权外键、去重键。MySQL 使用 ALTER/CREATE，不重建原业务表，不删除课程/题库/作答。有效的旧错题计划按 `user_id + from_question` 转为关联的习题计划；其他旧任务仍为 custom。旧任务原来的 done 状态保留，不从旧作答导入进度。旧 schema 没有精确完成时间，所以仅迁移前已 done 的任务用 created_at 作为历史近似 completedAt；对应旧错题题目也标为完成，使已完成状态与 1/1 进度一致。旧未完成任务保持 0 进度。不会为升级前完成任务补发通知。旧任务提醒时间为 null。

0006 只新增规范化 `task_subtasks` 表；每个旧 custom 任务迁移为同标题单项，保留原 done、父任务 ID、日期和完成时间。exercise 不添加小任务，原任务、题目、作答、提醒数据均不更改。新体验账号也创建真实的单项清单。

新选择题提交与任务进度、完成通知处于同一事务。MySQL 任务行锁使同一计划的并发提交、编辑和到期检查串行；通知唯一键 `(user_id, task_id, kind, occurrence_at)` 按提醒时刻去重，完成通知使用固定 occurrence_at 保证只生成一次。降级会移除新增进度和提醒表/字段；原任务与作答保留，新增进度与提醒记录需在降级前备份。

调度器每约 2 秒检查一次到期任务，单批最多 1000 个；同步 ORM 在工作线程执行。重启会补查已到期且未完成的计划。单进程 Hub 只发送刷新信号，数据库始终保存权威记录。多 worker / 多实例部署前必须加入 Redis 等共享消息总线，再保证各实例的连接都收到已提交变更。当前请使用单 worker。

## 计划和作答

`GET/POST /api/v1/tasks` 与 `GET/PATCH/DELETE /api/v1/tasks/{task_id}` 保留原字段，并增加：

| 字段 | 语义 |
| --- | --- |
| kind | custom（默认）或 exercise |
| courseId | 习题所属本人课程，custom 为 null |
| questionIds | 计划选定题目 ID，exercise 至少 1 道、不重复、最多 1000 道，全部属于本人同一课程 |
| subtasks | 有序 `{id,title,done}` 清单；exercise 返回空数组 |
| completedQuestionIds | 仅本计划内成功保存过提交的题目 |
| reminderAt | 带时区 ISO8601 或 null；保存为 UTC，响应以 Z 结尾 |
| completedAt | 最近完成时刻的 UTC ISO8601；未完成为 null，迁移前已完成的旧记录使用创建时间近似 |

自定义计划是父任务与小任务清单，只有全部小任务勾选才自动完成；取消任一项或新增未完成项会清空 completedAt 并恢复待办。父任务禁止直接 PATCH done（包括 false）。习题计划不能手动 PATCH done（包括 false），其 target 由后端生成 `/app/practice?task=ID&course=ID`。创建后 kind/courseId/questionIds 固定；修改选题应删除后新建，避免旧作答混入新计划。可编辑标题、描述、分钟数、日期、提醒时间。PATCH reminderAt=null 清除提醒，未设置提醒时间时不编造默认时间。

`POST /api/v1/attempts` 可增加 taskId，响应追加 task（普通作答为 null）。习题计划中的每道题成功提交一次即完成，**不要求答对**；答错仍按原判题规则进入错题本。非法选择、其他用户/课程/计划外题目、失败事务不推进进度。submissionId 同时绑定原作答与原计划，普通历史作答的幂等键不能用于新计划，跨计划复用返回 409。刷新从服务器 completedQuestionIds 恢复，无需前端依据历史成绩推断。

`POST /api/v1/mistakes/{question_id}/plan` 创建关联该题的 exercise 计划；未完成时按原 active_key 去重，完成后可再次新建。删除计划会删除其进度和通知，但保留历史作答；删除关联课程时由所有权外键清理对应习题计划。无关联课程的自定义任务不受影响。

## 持久化通知 REST

### GET /api/v1/notifications

需 Bearer，支持 limit=1..100（默认 50）、offset>=0。响应 `{items,total,unreadCount,limit,offset}`，按创建时间倒序。unreadCount 为账号总未读数，不受分页影响。

Notification 字段：`id,taskId,kind,title,body,target,createdAt,read,taskDone`。kind 为 due/completed；标题、正文与目标为生成时快照，taskDone 为当前任务状态。完成任务不会移除到期记录或完成记录。同一任务同一提醒时刻最多一条 due；更改为不同提醒时间可再次提醒，改回已提醒的同一时刻不会重复。每任务最多一条 completed，完成后不再新生成到期提醒，恢复再完成也不重复完成通知。

### PATCH /api/v1/notifications/{notification_id}

请求 `{read:true}`，返回更新后的 Notification。仅可操作本人记录；不存在与他人记录均返回 404。重复操作幂等。

### POST /api/v1/notifications/read-all

将本人所有未读记录设为已读，响应 `{updated:int}`。事务成功提交后向当前账号连接发送变更信号。

## WebSocket

连接 `/api/v1/notifications/ws`；URL 不接受令牌或任何查询参数。浏览器 Origin 必须在 CORS_ORIGINS 中；无 Origin 的原生客户端仍需相同令牌鉴权。

连接后 5 秒内首帧发送 `{type:'authenticate',token:'登录令牌'}`。合法会话收到 `{type:'ready'}`，此时客户端应 GET notifications 和 tasks 以恢复快照。无效/过期令牌关闭为 4401；禁止 origin/URL 参数为 4403；鉴权后非法帧为 4400。

收到 `{type:'notifications.changed'}` 后重新拉取通知与计划。发送 `{type:'ping'}` 会收到 `{type:'pong'}`。定时检查及每次收到客户端消息都重新查询会话，所以登出/过期后连接会关闭。仅向同一用户的连接发信号；单个发送有超时，关闭生命周期清理连接。失败/断线期间的数据保留在数据库，客户端重连后读取快照即可恢复。浏览器关闭时不承诺操作系统推送。

## 验证边界

业务回归使用临时 SQLite，迁移验证 upgrade/downgrade 与 ORM 元数据一致。SQLite 不模拟 MySQL 的 FOR UPDATE 行锁和并发唯一键等待；真实 MySQL 并发测试仍需在专用隔离测试库启用 RUN_MYSQL_TESTS。真实网络握手另使用 Uvicorn + websockets15.0.1 +临时 SQLite 验证，不能仅凭 TestClient 判断生产 WebSocket 可用。不要将开发用 SQLite 测试服务连接到真实账号。


## 自定义计划小任务 API（0006）

POST `/api/v1/tasks` custom 可传 `subtasks:[{title,done?:false}]`，1～100 项，每项去除首尾空格后 1～200 字。不传清单兼容创建与父任务同标题的一个小任务；显式 null、空清单或 done=true 返回 422。exercise 不能传 subtasks。

PATCH `/api/v1/tasks/{task_id}` 可传 `subtasks:[{id?,title,done?}]` 原子替换清单：已有 ID 保留数据库当前 done，忽略编辑快照 done；缺失旧 ID 删除，新增项不传 ID 且固定未完成。以数组顺序保存。重复、外来或已删除 ID 返回 409，空白标题、空清单、新增项 done=true 返回 422；失败时父任务和全部子项均不变。删除最后一个未完成项后，剩余项全部完成则父任务自动完成。

PATCH `/api/v1/tasks/{task_id}/subtasks/{subtask_id}` 请求 `{done:boolean}`，返回完整 TaskOut。仅本人当前父任务内的小任务可操作，无权或不存在返回 404。先获取父任务行锁，再以当前锁定读取加载子项，保证 MySQL 并发勾选不会因旧快照丢失父任务完成状态。勾选、清单保存和父任务聚合、持久化完成通知在同一事务，成功提交后沿用 `notifications.changed` 刷新。
